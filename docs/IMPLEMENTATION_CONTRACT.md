# Contrato de implementación

Node 24 + Express 5 + SQLite (node:sqlite), React + Vite. API misma procedencia /api. Respuesta {data}; listas {data,meta:{page,pageSize,total,totalPages}}. Errores {error:{message,fields?}}. Sesión cookie HttpOnly `sgc_session`, CSRF: login y GET /auth/me devuelven {data:{user,csrfToken}}; mutaciones autenticadas requieren X-CSRF-Token. Permisos y roles vienen como arrays de strings en user. Códigos rol: administrador, coordinador, instructor, participante, rrhh, gerencia.

Campos usuario: id,first_name,last_name,email,document,active (boolean),department,specialty,roles:string[],permissions:string[]. POST /users acepta esos campos + password; PUT /users/:id los campos excepto password opcional; roles se asignan con PUT /users/:id/roles {roles:string[]}. GET /users?search=&role=&page=&pageSize=. GET /users/:id. /instructors y /participants (GET/POST/PUT :id) equivalentes restringidos al rol apropiado: coordinador puede crear/editar usuarios de esos roles sin asignar permisos administrativos. GET /roles devuelve [{id,code,name,permissions:string[]}]; GET /permissions [{code,name}]; PUT /roles/:id {name,permissions:string[]}. Roles fijos, permisos editables salvo administrador protegido.

Permisos: users.manage,roles.manage,trainings.manage,trainings.view_all,people.manage,teaching.manage,learning.view,history.view,reports.view,certificates.manage. Administrador todos; coordinador trainings.manage/trainings.view_all/people.manage/certificates.manage; instructor teaching.manage; participante learning.view; rrhh history.view/trainings.view_all/reports.view; gerencia reports.view/trainings.view_all.

GET /auth/me; POST /auth/login {email,password}; POST /auth/logout. GET /config {trainingStatuses,modalities,attendanceStatuses,gradeMin:0,gradeMax:20,passingGrade:14,minAttendance:80}.

Training: id,code,title,description,start_date,end_date,start_time,end_time,modality (presencial,virtual,hibrida),location,capacity,status (planificada,programada,en_curso,finalizada,cancelada),instructor_id nullable,responsible_id,created_at,updated_at. GET /trainings?search=&status=&from=&to=&page=&pageSize= filtra por alcance: instructor asignado, participante inscrito, view_all global. Filas incluyen instructor_name,enrolled_count,available_seats. POST /trainings y PUT /trainings/:id. GET /trainings/:id agrega sessions y enrollments; enrollments solo el propio para participante. Inscripción: id,training_id,participant_id,status (inscrito,cancelado),created_at,participant_name,participant_email,attendance:[{id,session_id,status}],attendance_percentage,evaluation:{grade,observation,...}|null,certificate:{id,code,status,...}|null. POST /trainings/:id/enrollments {participant_id}; PATCH /enrollments/:id {status}. Sesiones: id,training_id,date,title. POST /trainings/:id/sessions {date,title}; PUT /sessions/:id/attendance {records:[{enrollment_id,status:(presente,ausente,tardanza)}]}. PUT /enrollments/:id/evaluation {grade,observation}. POST /enrollments/:id/certificate. GET /certificates/:id/download PDF. GET /history?participant_id= incluye array de inscripciones con training_title,training_code,start_date,end_date,training_status,instructor_name y lo anterior; participante sólo propio, rrhh history.view puede otro.

GET /reports?from=&to=&status=&training_id=&instructor_id= -> {summary:{trainings,participants,enrollments,capacity,available_seats,attendance_percentage,average_grade,certificates},by_status:[{status,count}],trainings:[{id,code,title,status,capacity,enrolled_count,available_seats,attendance_percentage,average_grade,certificates}]}. GET /reports/export.csv mismos filtros. GET /dashboard -> resumen adaptado al usuario {trainings,users,roles,enrollments,certificates} y upcoming:[...].

Backend común exportado por root: server/db.js export createDatabase(path='...') -> db DatabaseSync con migraciones ya aplicadas, transaction(db,fn) BEGIN IMMEDIATE/commit/rollback, now() ISO; server/errors.js export HttpError(status,message,fields?), validate(schema,input) -> parsed, asyncRoute; server/security.js export requirePermission(...permissions) cualquiera, requireAuth; req.user user hidratado; server/constants.js export ROLES,PERMISSIONS,TRAINING_STATUSES,MODALITIES,ATTENDANCE_STATUSES,GRADE_MIN,GRADE_MAX,PASSING_GRADE,MIN_ATTENDANCE. server/app.js export createApp({db,secureCookies=false,rateLimitEnabled=true}) -> Express app. Domain agent export createTrainingRouter(db) in server/routes/trainings.js (mounted /api, route paths completos) y createReportingRouter(db) server/routes/reporting.js.

DB schema: users(id,first_name,last_name,email UNIQUE NOCASE,document UNIQUE nullable,password_hash,active,department,specialty,created_at,updated_at); roles(id,code UNIQUE,name); permissions(code PK,name); user_roles(user_id,role_id); role_permissions(role_id,permission_code); sessions_auth(token_hash PK,user_id,csrf_token,expires_at); trainings campos arriba; enrollments(id,training_id,participant_id,status,created_at,updated_at,UNIQUE(training_id,participant_id)); training_sessions(id,training_id,date,title,UNIQUE(training_id,date)); attendance(id,enrollment_id,session_id,status,recorded_by,updated_at,UNIQUE(enrollment_id,session_id)); evaluations(id,enrollment_id UNIQUE,grade,observation,recorded_by,updated_at); certificates(id,enrollment_id UNIQUE,code UNIQUE,status,issued_at,issued_by,participant_name,training_title,start_date,end_date,grade,attendance_percentage); audit_log(id,user_id,action,entity,entity_id,created_at).

Finalizadas/canceladas no admiten nuevas inscripciones ni cambios académicos. Certificado sólo finalizada, inscripción activa, al menos una sesión, todas las sesiones registradas, asistencia >=80% (presente/tardanza), nota >=14. Inscripciones, reducir capacidad y certificar usan transacciones. Instructor sólo sus capacitaciones; participante sólo datos propios; nunca confiar en frontend.
